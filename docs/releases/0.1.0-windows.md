## Layout and performance revision

The left sidebar now has separate quota and history statistics destinations,
with Settings at the bottom. All pages use an independently scrolling content
area; Settings retains drafts after navigation. Default body/control text is
14px, supporting text 12px, and page titles 22px. Controls use 36px comfortable
or 32px compact sizing, scaling with typography and app zoom. Secondary actions
are grouped in keyboard-accessible disclosures. Browser verification includes
420px/320px widths, enlarged root typography, model comparisons and the theme
editor; bottom-edge menus open upward without leaving the viewport.

Automatic provider detection replaces manual path controls. Existing explicit
configurations are preserved; switching them to automatic is deliberate. Native
executable discovery and history availability do not enable account queries.
Model details compare cost, tokens and cached input per environment alongside
the original trends, cache, speed and cost breakdowns.

The initial static JavaScript graph totals 709,449 bytes, compared with
1,079,299 bytes before lazy loading (about 34% less). Settings, statistics,
the editor and OpenVSX ZIP handling load when needed; the market is not queried
until explicitly browsed or searched. Short-window history query allocations
drop substantially; the benchmark and limitations are in the acceptance record.

Managed cold-profile startup measurements use the exact executable above,
isolated state, disabled refresh, no sources/accounts and no development server.
Both revised runs exit 0 with startup, appearance, frontend-ready and shutdown
events. No attributable application or WebView process remains afterward.

| Measurement | Earlier baseline | Revised run 1 | Revised run 2 |
| --- | ---: | ---: | ---: |
| Frontend ready after native startup | 3.99s | 5.22s | 4.90s |
| Peak parent private memory | 72.86MB | 69.56MB | 69.87MB |
| Peak summed app/WebView private memory | 291.12MB | 217.17MB | 214.76MB |
| Peak summed working set | 488.37MB | 398.67MB | 398.19MB |

The observed startup measurements do not demonstrate a cold-start speedup.
WebView cold-profile creation and host load vary; an earlier separate baseline
also showed about 216MB private memory. These small samples are startup peaks,
not steady-state memory guarantees. Summed working sets can count shared pages
more than once. Query allocations and reduced initial code are reproducible
scope-specific improvements; no universal startup or RAM percentage is claimed.
